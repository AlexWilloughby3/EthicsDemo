## 1. Introduction

Schur numbers $S(k)$ measure how long $\{1, \dots, N\}$ can be $k$-colored with no monochromatic solution to $x + y = z$. The values $S(1) = 1$, $S(2) = 4$, $S(3) = 13$, $S(4) = 44$ are known, and $S(5) = 160$ was settled by a large SAT computation.

This paper is a **Level 2** case study. The theorem is old and true, but the new proof is mostly a machine artifact.

## 2. The formal statement (and why we trust it)

A formal proof only certifies the statement it proves. That statement must say what we *mean*. The human author wrote and audited the following statement (illustrative):

```lean
def SumFree (A : Finset ℕ) : Prop :=
  ∀ x ∈ A, ∀ y ∈ A, x + y ∉ A

theorem schur_three :
    (∃ c : Fin 13 → Fin 3, ∀ i, SumFree (colorClass c i)) ∧
    (∀ c : Fin 14 → Fin 3, ∃ i, ¬ SumFree (colorClass c i)) := by
  exact ⟨lower_bound, upper_bound⟩
```

Here `colorClass c i` is the set of $m \in \{1, \dots, N\}$ given color $i$. We checked by hand that `x = y` is allowed (as in the standard definition) and that the ranges are off-by-one correct.

## 3. Lower bound: an explicit coloring

The partition
$$\{1, 4, 10, 13\} \cup \{2, 3, 11, 12\} \cup \{5, 6, 7, 8, 9\}$$
of $\{1, \dots, 13\}$ is sum-free in each part. The third part works because $5 + 5 = 10 > 9$. For the first two parts, list all pairwise sums ($x = y$ included) and check that none lands back in the same part. This is a two-minute hand check, and we encourage readers to do it.

## 4. Upper bound: exhaustive case analysis

The AI prover reduces the problem by symmetry (permuting colors, and assuming WLOG $1$ has color $0$) and then performs a guided case split on the colors of $\{1, 2, 3, 4, 5\}$, propagating forced assignments. The resulting proof term has roughly 2,300 leaf cases, each closed by `decide`.

```lean
theorem upper_bound : ∀ c : Fin 14 → Fin 3, ∃ i, ¬ SumFree (colorClass c i) := by
  intro c
  wlog h1 : c 1 = 0 := by exact color_perm_reduce c
  rcases color_cases c 2 with h2 | h2 | h2 <;>
  rcases color_cases c 3 with h3 | h3 | h3 <;>
  -- … ~2,300 branches generated by the prover …
  all_goals (first | exact forced_conflict ‹_› | decide)
```

We do **not** have a human-readable account of why each branch fails. The Lean kernel certifies correctness, but no person currently holds the argument in their head.

## 5. Discussion

Should a result like Section 4 count as "known"? It is certainly *true*: the checker guarantees it. But it adds little to human understanding of *why* $14$ is impossible. Under the proposed guidelines, the yellow tag records this honestly. Readers can see exactly which parts of the paper they can learn from, and which parts they must take on the checker's authority.
